### Needs decision - all resolved (W1)
1. **Slow-loris / header-read timeout (#18)** - resolved, see row 18 (the TLS listener has a 10 s header-read timeout; `--localhost` plain HTTP is for testing only).
2. **Zombie SSE streams** - mitigated, partly accepted: ping every 15 s, `SO_KEEPALIVE` on the listening sockets (the host's `tcp_keepalive_time=60` now applies to **idle** half-open connections; verified on a running server: accepted sockets show the kernel keep-alive timer), HTTP/2 PING keep-alive in TLS mode (dead h2 peer dropped in about 30 s). A stream that is being pinged is never idle, so keep-alive does not fire for it; a dead HTTP/1.1 phone is dropped only when the kernel stops retransmitting (`tcp_retries2`, default 15 = about 15 minutes): **set `net.ipv4.tcp_retries2=8` (about 100 s)** together with the keep-alive sysctls. No application self-heal (a write into the send buffer succeeds, so there is no "last write failed" signal before the kernel aborts the connection) and the oldest stream is never evicted at the cap (tabs would fight) - accepted. Crate need for the real fix: `socket2 = "0.6"` as a direct dependency (per-socket `TCP_USER_TIMEOUT` / keep-alive intervals). `tests/server_listener.rs`.
3. **Fleet integrity of count posts** - resolved: negative adjustments / count variances in `JAR_EMPTY` / `JAR_CLEAN` and jars damaged / short on godown-transfer receipt write `DESTROYED` fleet events in the same transaction; surpluses write nothing (no invented purchases); `/jars/fleet` total is derived from stock + customer holdings. No `unexplained_delta` (no recorded opening balance, see API_REFERENCE 0.2-H). `tests/fleet_integrity.rs`.
4. **Adjustments above `batch.crates`** - resolved: `409 OVER_PRODUCED`, hard (no `confirm`, dry runs too), batch row locked first; covers positive adjustments and count surpluses; counts FG_READY + QC_QUARANTINE of the lot over every godown incl. TRANSIT. Accepted limitation: crates already shipped / scrapped are not counted, so it is a typo / double-entry guard rather than a reconciliation. In particular the restock paths (settlement returns, gate-pass / dispatch void) are never blocked, so crates that were on the road when a "found" adjustment was posted can push the total past `batch.crates` when they come back. `tests/over_produced.rs` (incl. a 12-way concurrency test).
5. **Idempotency edge** - resolved: a key left pending by the 30 s timeout (or a crash) stays reserved for 10 minutes (`409 IN_PROGRESS`, `details.outcome_unknown`) instead of 35 s, and the response is stored by a detached task so a caller that vanishes right after the handler finished still leaves a replayable key. Trade-off: a request cut off *before* it committed also blocks a retry with the same key for 10 minutes (the user repeats the action, which gets a new key). `pentest_idempotency.rs::timed_out_request_keeps_its_key_reserved_for_ten_minutes`.

### Residual risks (accepted)
Session key is JS-readable by design (XSS = account takeover; CSP `script-src 'self'` mitigates). No MFA. Single-process in-memory limiters (lost on restart, per process). Web Push delivery is at-most-once. `X-Forwarded-For` is never trusted, so behind a reverse proxy the per-IP limiter sees the proxy address (the per-account lockout still protects).
